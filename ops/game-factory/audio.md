# Аудио для игрового проекта

Это отдельная опциональная ветка. Без `audio.configurationPath` в конфигурации завода она недоступна. Изменение кода и тестирование не создают разрешение на реальный расход. Старый Python worker с явным `music:true` сохраняет прежний интерфейс; его нельзя считать защищённым новым проектным grant-механизмом.

## Приватная конфигурация

Конфигурация адаптера версии 1 содержит `enabled` (по умолчанию false), `pythonExecutable`, `musicScript` (проверенный `music_host.py` рядом с совместимым `music.py`), `stateDirectory`, `outputDirectory`, `secretFile`, `grantsFile`. Все пути абсолютные и канонические. Настройки, grants и ключ — приватные файлы 0600 с одной ссылкой, каталоги — 0700, владелец — пользователь сервиса. Управляемые файлы и состояние располагаются вне любых sourceRoots/рабочих игровых каталогов. Python и FFmpeg/FFprobe устанавливаются и проверяются оператором; модель их не выбирает.

`secretFile` — отдельный файл с единственным значением `APIFRAME_API_KEY=...`; он читается как текст, не выполняется и не подставляет shell-переменные. Не копируйте его в проект и не передавайте через аргументы модели. Чтение статуса не открывает этот файл и не выполняет сетевых вызовов.

## Одно прямое согласие — один резерв

Оператор создаёт приватный `grantsFile` вида `{ "version": 1, "grants": [] }`; пустой список не разрешает генерацию. Добавлять grant разрешено только после фактического прямого согласия основного владельца, отдельно определяющего один запрос, его точный prompt, проект/задачу и локальный лимит кредитов. Не генерируйте разрешение из модельного брифа, общего «сделай игру» или предположения о доступном балансе.

Каждая запись содержит:

- `id`: уникальный ID разрешения, 8–128 букв/цифр/`_`/`-`;
- `actorKey`, `projectId`, `taskId`, `briefRevision`: точный исполнитель и текущая задача;
- `promptSha256`: SHA-256 точной UTF-8 строки запроса без дополнительной нормализации;
- `provider: "apiframe"`, `model: "suno"`, `modelVersion: "V5_5"`;
- `maxCredits`: целый локальный лимит не менее 11; `estimatedCredits: 11`;
- `expiresAt`: срок разрешения нового POST, ISO timestamp с timezone;
- `approval`: `kind: "host_verified_direct_user"`, `approverActorKey`, `chatJid`, `channelChatId`, `senderId`, `messageRef`, точная `quote` и `quoteSha256`.

Основной хост повторно проверяет, что approval указывает на сохранённое прямое Telegram-сообщение основного владельца, а не на текст модели, пересланное сообщение или строку из чужого чата. Сам текст quote не предоставляет прав: grant-файл создаётся оператором, а модель не имеет действия для его записи. Исполнитель может быть другим явно указанным участником того же проекта; согласие на оплату даёт основной владелец.

Цена 11 credits и модель V5_5 сверены с [официальной документацией APIFrame Suno](https://apiframe.ai/docs/music/suno) 2026-11-04. Это локальная оценка и резервация, **не гарантия потолка внешнего списания**. Фактическая стоимость хранится как unknown, пока ответ провайдера не содержит подтверждённый `creditCost`. Не выводите стоимость по разнице общего баланса.

## Исполнение и восстановление

Существующий реестр завода хранит `factory_audio_bindings` с уникальными job ID и grant ID. `audio_dispatch` требует текущего claim и сначала атомарно сохраняет связанный резерв, затем вызывает Python вне SQLite transaction. В Python намерение отправки записывается до POST. Принятое задание имеет отдельный provider job ID; при потерянном ACK резерв остаётся unknown и повторный POST запрещён. Новая очередь или фоновый исполнитель не создаются.

`audio_status` — локальное чтение; `audio_refresh` — максимум одна сверка существующего provider ID; `audio_import` — получение уже завершённых файлов и подготовка двух MP3-петель в новом приватном каталоге, затем неизменяемое копирование в проект. Исходная игра не переписывается. Ассеты имеют статус candidate, hash, происхождение, исходную brief revision, известную либо неизвестную стоимость и необходимость проверки прав. Для приёмки нужны отдельное прослушивание/проверка стыка и `asset_review`.

Для остановки новых расходов установите audio `enabled:false`. Уже принятые результаты можно читать, сверять и получать после expiry и отключения новых запросов, пока исходный grant не изменён/удалён, конфигурация привязки и проектные права действуют. Поправка брифа не уничтожает оплаченные файлы: они импортируются как исторические кандидаты, но не принимаются как текущие. Для отзыва доступа удалите grant; даже cached output тогда не раскрывается. Не удаляйте reservation/journal и не выпускайте новый grant для обхода unknown: сначала вручную сверьте реальный исход у провайдера.

Возвраты модели не содержат API URL, secret path, provider error body, approval quote или приватный output path. Статус доставки, качество музыки и права на коммерческое использование не устанавливаются автоматически. Рабочее включение требует отдельной проверки на установленной версии; fixture-тесты не являются реальной генерацией или разрешением тратить средства.
